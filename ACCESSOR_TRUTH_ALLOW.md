# ACCESSOR_TRUTH_ALLOW — justified ACCESSOR-TRUTH exceptions (perl)

`- <method> — reason` excuses one `accessor_truth.py` finding.

`accessor_truth.py`'s perl `def_re` is `sub\s+(name)` — it only recognizes methods
defined with an explicit `sub`. It cannot see accessors generated by Moo's
`has 'name' => (...)`, which is how this SDK (like all Moo-based Perl) declares an
attribute's read accessor. The three entries below are REAL, callable accessors —
`has 'schema_utils'/'verb_registry'/'security'` on
lib/SignalWire/SWML/Service.pm (each a `lazy` attribute mirroring the Python
reference's SWMLService introspection accessors) — documented accurately in
docs/swml_service_guide.md. The clean permanent fix is to also match
`has\s+['"]name['"]` in the porting-sdk perl def_re; flagged to the orchestrator.

- schema_utils — Moo `has 'schema_utils'` accessor on SWML/Service.pm (lazy; returns the SWML schema singleton); gate's `sub`-only def_re can't see Moo `has` accessors (perl, 2026-07-11)
- verb_registry — Moo `has 'verb_registry'` accessor on SWML/Service.pm (lazy; VerbHandlerRegistry-parity handler map); gate's `sub`-only def_re can't see Moo `has` accessors (perl, 2026-07-11)
- security — Moo `has 'security'` accessor on SWML/Service.pm (lazy; SecurityConfig accessor); gate's `sub`-only def_re can't see Moo `has` accessors (perl, 2026-07-11)
